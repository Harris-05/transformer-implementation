# KV-Cached Generation Implementation Plan

**Goal:** Complete assignment Task 3 with explicit cached and uncached greedy
decoding, token agreement checks and reproducible GPU measurements.

**Architecture:** A batch-one, unpadded forward-pass decoder owns cache reuse,
absolute positions, growing masks and EOS stopping. A separate experiment runner
loads the pinned 4-bit selected adapter and saves correctness and benchmark logs.
An upload bundle and Colab notebook follow the existing project workflow.

**Tech stack:** Python, PyTorch, Transformers 5.15.1 DynamicCache, existing PEFT
0.21.2 adapter and bitsandbytes quantization. No dependency upgrades.

**Spec:** `GenAI_Assignment#2.pdf`, Task 3 and rubric D1-D3; user approved proceeding
with manual cached/uncached greedy generation and Colab measurements.

## Decisions and constraints

- Use model forward calls plus DynamicCache; no generate() in either decoder.
  HF generate() is an independent correctness reference only.
- Preserve all frozen EDA, model-input, baseline and training source files.
- Reject padded/multiple/empty inputs explicitly; use only development records.
- Explicit position_ids are supported by the pinned Qwen3 forward signature;
  do not copy obsolete cache_position examples into this version.
- Correctness: seeded tiny real Qwen3 tests at three input/output lengths,
  prefill + one-token cache growth traces, EOS and repeat-call isolation.
- GPU: same selected adapter in evaluation mode and SDPA for both paths;
  three input lengths (128,256,512) crossed with three output lengths (16,32,64).
  Fixed-token stress prompts ignore EOS and are labelled synthetic; clinical
  full prompts separately use normal EOS and max_new_tokens=128.
- Three warmed, synchronized repetitions; alternate path order. Save all raw
  timings, medians, ranges, allocated/reserved peaks and initial memory.
- Save first-divergence diagnostics; never repair a mismatch or call it a pass.
- Colab results cannot be claimed locally: laptop checks use miniature CPU models.
