# Application, Final Evaluation and Report Implementation Plan

**Goal:** Complete work independent of the pending speculative GPU run.

**Spec:** `GenAI_Assignment#2.pdf`, Tasks 2/6, final evaluation and submission.
**Architecture:** A localhost Python browser application calls existing explicit
decoders through a lazy model service. A separate final evaluator uses the frozen
prompt/scorers on the prescribed test group. An IEEE LaTeX paper consumes verified
development/optimization artifacts and clearly marks pending final results.
**Stack:** Python standard-library HTTP server, HTML/CSS/JavaScript, existing
PyTorch/Transformers/PEFT; IEEEtran LaTeX, matplotlib. No frontend build service.

## Constraints and rulings

- Existing user instruction to start the remaining work authorizes execution;
  no additional design approval pause. Local app, not public deployment.
- Frozen EDA, training, baseline, preparation and decoder files stay unchanged.
- No model downloads/training on this laptop. GPU/live full-model verification
  remains explicit. Do not inspect held-out clinical content during development;
  the final-evaluation command opens it only when explicitly executed.
- No speculative GPU numbers invented. Preserve the closed KV mismatch.
- Existing enclosing Git repository is the user's home; no broad git operations.
- App requests accept only note/type/criterion text; never expert/GPT predictions.
- Explain decisions through exact cited text, not newly invented clinical facts.
- Ordinary/speculative live comparison shares target precision/backend and inputs.
  CPU unquantized FP32 and CUDA NF4/FP32 are distinct deployment protocols.
- Only one model operation at a time; no patient records logged or saved by default.
- UI direction: dealt editorial workspace, Instrument Sans/Serif, deep teal accent,
  source sentence IDs as the product-specific evidence navigation. Local fonts
  preferred; system fallback keeps offline operation functional.
